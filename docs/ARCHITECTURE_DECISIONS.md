# Architecture Decision Records

Material architecture decisions are recorded before or with implementation. Records are immutable after acceptance except for status and links to superseding records.

## Statuses

- Proposed
- Accepted
- Deprecated
- Superseded
- Rejected

## Process

1. Copy `docs/ADR_TEMPLATE.md` to `docs/adr/NNNN-short-title.md`.
2. Assign the next sequential number and set status to Proposed.
3. Record context, constraints, considered alternatives, and evidence without inventing metrics.
4. Include security, privacy, data migration, compatibility, rollback, and verification implications.
5. Mark Accepted only after the decision owner approves it.
6. Never rewrite an accepted decision to change history; create a superseding ADR and cross-link both records.
